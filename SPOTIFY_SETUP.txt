A PROFECIA — MÚSICA, SONS E SPOTIFY V20

ESCOPO
Esta versão altera somente Música e Sons. O restante da aplicação foi preservado.

1. SPOTIFY
- OAuth 2.0 Authorization Code com PKCE para aplicação web no navegador.
- Client Secret NÃO é usado no frontend.
- Client ID é público e pode ser configurado no painel de Música e Sons.
- Access token fica na sessão atual; refresh token fica associado à identidade local (Mestre ou Player) para permitir renovação sem novo login enquanto o refresh token continuar válido.
- O estado OAuth (state) e o code verifier são validados por identidade.
- A Redirect URI usada é a URL exata da página atual, sem query/hash.

2. CONFIGURAÇÃO NO SPOTIFY
- Crie um aplicativo no Spotify for Developers.
- Cadastre como Redirect URI EXATAMENTE o endereço mostrado pelo site.
- Em produção, use HTTPS. Em desenvolvimento, HTTP só é aceito para 127.0.0.1/localhost conforme as regras atuais do Spotify.
- Informe o Client ID no site.
- Não coloque Client Secret no código.

3. PERMISSÕES
A conexão solicita somente as permissões necessárias para o recurso implementado:
- streaming
- user-read-email
- user-read-private
- user-read-playback-state
- user-modify-playback-state
- user-read-currently-playing

4. REPRODUÇÃO
- Links/URIs do Spotify são identificadores de conteúdo; nunca são tratados como MP3.
- A reprodução completa no navegador usa o Spotify Web Playback SDK.
- O usuário precisa de uma conta Spotify Premium para o Web Playback SDK.
- Cada navegador reproduz sua própria sessão Spotify. O site não redistribui nem retransmite o áudio para outros usuários.
- O botão Abrir no Spotify continua disponível como alternativa.
- O navegador pode exigir uma interação do usuário antes de iniciar áudio.

5. MESTRE E PLAYER
- Mestre e Player possuem identidades de autenticação Spotify separadas no mesmo navegador.
- A trilha escolhida pelo Mestre continua registrada no estado do site.
- Cada usuário precisa autorizar sua própria conta para reprodução completa no próprio navegador.
- Em uma aplicação puramente estática, a seleção global do estado não é uma sincronização em tempo real entre dispositivos; isso exigiria um backend/banco compartilhado.

6. ÁUDIO LOCAL
- O Mestre pode enviar áudio local.
- Trilha local: até 25 MB, armazenada no IndexedDB do navegador.
- Sons: até 8 MB, armazenados no IndexedDB do navegador.
- Arquivos locais não são enviados a um servidor nesta versão.

7. LIMITAÇÕES DO SPOTIFY
- O Web Playback SDK está sujeito às políticas e limitações atuais da plataforma.
- O Spotify não pode ser usado como sistema de transmissão não interativa/broadcast.
- Conteúdo Spotify não deve ser sincronizado com mídia visual.
- Se o token expirar, a aplicação tenta renová-lo; se a renovação não for possível, o usuário deverá autorizar novamente.
- Refresh tokens também possuem ciclo de vida e podem exigir nova autorização.

8. TESTE
1) Hospede o site em HTTPS ou use 127.0.0.1/localhost em desenvolvimento.
2) Cadastre a Redirect URI exata exibida na tela.
3) Informe o Client ID.
4) Clique em Entrar com Spotify.
5) Autorize as permissões.
6) Volte ao site.
7) Se a conta for Premium e o SDK estiver disponível, clique em Reproduzir no navegador.

IMPORTANTE
Nenhuma implementação frontend consegue tornar o Spotify independente das exigências da própria plataforma. A aplicação implementa o fluxo oficial, mas Premium, autorização, Redirect URI, disponibilidade do SDK, limites da conta/app e políticas do Spotify continuam sendo requisitos externos.
